📋 현재 설정 평가

Sonnet 5 Default는 좋은 선택입니다:
낮은 비용에서 강한 결과가 필요하면 Sonnet이 기본값에 가깝습니다 
EvoLink

🎯 작업 유형별 모델 전략

당신의 개발 패턴에 맞게:

1️⃣ GAS 복잡 로직 개발 → Sonnet 5 (현재 유지)
Claude Code 주력 작업(여러 파일 동시 수정, 리팩터링)은 Sonnet이 기본값입니다 
SlideParser.js, publishLecture() 같은 핵심 로직 작업

2️⃣ 단순 코드 작업 → Haiku로 전환하여 비용 절감
단순 코드 자동완성이나 짧은 함수 생성은 Haiku로 내려서 비용과 속도 둘 다 챙깁니다 
매개변수 수정, 버그 수정, 주석 작성 등

3️⃣ 아키텍처/성능 분석 → Opus 고려
Opus는 다단계 추론이 필요한 문제 해결에 더 적합합니다: 복잡한 오류 메시지, 아키텍처 선택, 성능 병목 현상에 대한 분석 설명 
시스템 재설계, 병목 분석 시에만

⚙️ Claude Code에서 모델 변경하는 법
# 현재 설정 확인
/status

# 모델 변경 (전역)
/set-model haiku    # Haiku로 변경
/set-model sonnet   # Sonnet으로 돌아가기
/set-model opus     # Opus로 변경 (복잡 작업용)

# 세션별 모델 지정 (새 터미널에서)
/set-model haiku-only  # 이 세션만 Haiku 사용
💡 효율적인 운영 방법

당신의 불규칙한 사용 패턴에 최적화:

상황	추천 모델	비용 절감
강의 시스템 핵심 개발	Sonnet 5	기본값
버그 수정, 미세 조정	Haiku	~30-40% 절감
시스템 재설계 필요 시	Opus	필요할 때만
📊 구체적 적용 예

당신의 현재 마일스톤 기준:

Publish Engine Stage 2 개발 → Sonnet 5
System B 폼 연동 테스트 → Haiku로 전환
한도 초과 우려 시 → 비용 많이 드는 작업은 Haiku로 내려감

결론: 모델을 고정하지 말고, 작업 난이도별로 전환하면서 사용하는 것이 가장 효율적입니다.
